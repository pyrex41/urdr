# M1.5 status: the earned exit demonstration

Status: **the seven-item exit demonstration is production-real** — the
chain runs through `urdr.run.execute` on the partition-retry reference
scenario, and every verdict in it comes from the property engine over a
recorded fact trace. The synthetic marker oracle, the stub counter
world, and the hand-written verdicts of the Wave I demo are deleted.
Evidence lane for the M1.5 waves is **shen-go** (`make conformance
REQUIRED_IMPLS=shen-go`); the full four-port sweep remains separate
work, exactly as `docs/status/m1.md` records for Waves E–I.

## What is now claimed

The integration suite (`shen/tests/integration/run-tests.shen`,
Bifrost case `m1-integration`) demonstrates, in one program, with no
fixture verdicts and no marker oracles:

1. **Discovery** — `urdr.run.execute` on
   `scenarios/abstract/partition-retry.shen` (declared seed, budget,
   routes, model bindings; reference models in
   `shen/run/models/partition-retry.shen`) explores two passing
   schedules and discovers on attempt 2 a schedule where the injected
   partition of `{c}` lands while the server's reply is in flight; the
   client's retries meet the cut fabric and it gives up. The declared
   liveness property (`client-ack`, deadline 8) fails with no witness
   and the declared temporal property (`request-served`,
   always-eventually) fails with the first unanswered request as its
   witness — both from `urdr.properties.evaluate-all` over the world's
   recorded facts.
2. **Shrink** — `urdr.shrink.minimize` under the failure-signature
   gate, with an EVAL that re-drives the initial world through
   `urdr.replay.run` and re-evaluates the declared properties
   (certificate.shen §7's candidate rule). The minimized transcript is
   strictly shorter and still fails with the identical signature.
3. **Replay** — the minimized artifact is re-driven, recorded, and
   independently verified (`urdr.replay.verify` → `verified`), and the
   re-driven verdicts reproduce the discovered failure signature.
4. **NetKAT** — the partition policy yields symbolic `unreachable` for
   a→c and the open-fabric a→b reachability witness is `confirmed`
   (unchanged from M1; re-run against the same declared topology).
5. **NetworkPolicy** — default-deny + multi-peer compiles with the
   isolation claim and `spec-semantics-only` marker; over-permissive
   allow-all admits an unintended flow (unchanged from M1).
6. **Certificate** — the driver's own modeled-run certificate of the
   discovered run: status **FAIL** (controls satisfied, a property
   verdict failed), achieved profile `modeled-d1-analog`, abstract
   event log with zero non-`pure`/`modeled` entropy classes, marker
   `modeled-world-only`, and the ADR 0008 `models` field committing
   the full roster binding
   (`client:pr-client@a,…,server:pr-server@c`).
7. **Gate** — the suite is Bifrost case `m1-integration` with program
   and golden pinned in `bifrost.suite.json` and
   `scripts/bifrost-gate`; `make conformance REQUIRED_IMPLS=shen-go`
   ends `status PASS 13/13` and `make quality` is green.

Supporting change (kernel, digest-preserving):
`urdr.eventlog.state-digest` now encodes the snapshot under the
m1-large profile — the profile the snapshot's own per-component state
digests and facts root already use (ADR 0008 D1's reasoning: a state
hash has no content-address escape hatch). A five-component,
eight-route world snapshot decodes to ~330 nodes and can never fit the
m0 profile's 256-node budget, so the m0 bound made every legally
reached scenario-scale world unhashable. Profiles bound, they never
change encoding bytes, so every previously valid digest is
byte-identical and no golden outside the rewritten integration suite
moved.

## What is still not claimed

Follows the `docs/status/m1.md` non-claims table; everything there
that is not restated here is unchanged.

| Claim | Status |
| --- | --- |
| D0–D3 whole-system profile | **not claimed** (certificates stay `modeled-world-only`) |
| Four-port identity for the changed suites (integration; eventlog-touching suites) | **not claimed** — pending the port sweep; M1.5 evidence lane is shen-go |
| Built-in net/timer/fault models resolvable under the driver | **not claimed** — the roster binds reference process models for `fault-0`/`net-0` because the built-in fault model republishes its menu every step (a driver run would never quiesce) and the built-in net/timer alternatives need deliver-input/fire-input wrapping; deferral recorded in `shen/run/run.shen` and `shen/run/models/partition-retry.shen` |
| Scenario-declaration threading into model init-builders | **not claimed** — init-builders receive the roster record and network baseline only, so `pr-fault`'s partition domain `{c}` mirrors the declared fault domain rather than reading it |
| CNI / live NetworkPolicy fidelity | **not claimed** (`spec-semantics-only`, unchanged) |
| Late-witness liveness failures under the driver | **not claimed** — driver runs schedule at the current logical time, so the discovered violation is the no-witness form; time-advancing schedules await timer integration |
